# Документация по развертыванию (Deployment)
В директории **./../../deploy** содержатся конфигурационные файлы и скрипты, необходимые для сборки, запуска и отладки всей экосистемы IoT-бэкенда. Архитектура поддерживает две независимые стратегии развертывания: Легковесная локальная разработка (Docker Compose) и Полноценная оркестрация в кластере (Kubernetes / Minikube).

## Стратегия 1: Легковесная локальная разработка (Docker Compose)
Используется, когда вы активно пишите и дебажите код приложений esp-server или esp-worker локально в вашей IDE (например, запускаете через "go run"), и вам нужна только готовая инфраструктура в бэкграунде.

Задействованные файлы:
-	docker-compose.yml: Запускает внешние зависимости. Поднимает одиночный брокер Kafka (в режиме KRaft) и веб-интерфейс Kafdrop.
-	restart_containers: Вспомогательный скрипт, который полностью перезапускает стек Docker Compose, очищает старые сообщения и вручную создает обязательный набор топиков Kafka: root, logs, pins, actions.

Как использовать:
1.	Запустите окружение командой: docker compose up -d
2.	Инициализируйте топики скриптом: ./restart_containers
3.	Запускайте Go-сервисы на хост-машине с подключением к Kafka по адресу localhost:9092.

## Стратегия 2: Полноценный локальный кластер (Kubernetes / Minikube)
Используется для интеграционного тестирования всей системы в условиях, максимально приближенных к проду, когда и сами сервисы бэкенда, и инфраструктурные брокеры изолированы внутри единой сети Kubernetes.
1.	Инфраструктурный слой (Запуск в первую очередь)
-	mosquitto.yaml: Разворачивает MQTT-брокер Eclipse Mosquitto. Создает сервис типа LoadBalancer и выделенный порт NodePort 31883, позволяющий реальным микроконтроллерам (ESP8266, Wemos D1 mini) из вашей домашней Wi-Fi сети отправлять телеметрию.
-	kafka-stack.yaml: Разворачивает Kafka внутри кластера с включенным автосозданием топиков. Также поднимает Kafdrop, веб-интерфейс которого выводится на NodePort 31000.

2.	Прикладной слой (Запуск во вторую очередь)
-	apps-stack.yaml: Описывает деплоймент вашей бизнес-логики. Внутри деплоймента esp-server настроен initContainers, который пингует Kafka и проверяет/создает топики до старта основного приложения. Разворачивает esp-server (тег образа v4) и esp-worker (тег образа v2). Политика imagePullPolicy Never заставляет K8s использовать локально собранные образы. Публикует REST API сервера наружу через сервис LoadBalancer на NodePort 31080.

3.	Скрипт автоматизации управления
-	start-cluster.sh: Главный пульт управления для macOS, автоматизирующий рутину: проверяет и включает Docker Desktop, стартует Minikube, очищает порт 1883 от зависших процессов, запускает в фоне minikube tunnel, настраивает kubectl port-forward для Mosquitto на адрес 0.0.0.0:1883 и автоматически открывает веб-панель Kafdrop.
Шпаргалка по командам запуска
-	Пишу код бэкенда в IDE (нужна только Kafka): Выполнить "docker compose up -d && ./restart_containers"
-	Тестирую систему целиком в K8s: Выполнить "./start-cluster.sh"
-	Обновил код бэкенда: Выполнить "kubectl apply -f apps-stack.yaml"
-	Хочу очистить и сбросить только инфраструктуру K8s: Выполнить "kubectl delete -f kafka-stack.yaml -f mosquitto.yaml"
Сводная таблица портов и сетевых адресов
-	REST API бэкенда (esp-server): Доступен по адресу http://127.0.0.1:80 (благодаря туннелю) или через NodePort 31080.
-	MQTT Брокер (mosquitto): Слушает внешние подключения на 0.0.0.0:1883 (благодаря port-forward) или через NodePort 31883.
-	Панель управления Kafka (kafdrop): Доступна на http://127.0.0.1:9000 (в Docker Compose) или через NodePort 31000 (в Minikube).
