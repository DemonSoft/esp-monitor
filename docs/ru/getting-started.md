# Быстрый старт

## Предварительные требования

Перед началом работы убедитесь, что у вас доступны следующие инструменты:

- Go
- Docker и Docker Compose
- при необходимости PlatformIO для сборки прошивки
- при необходимости Minikube и kubectl для развертывания в Kubernetes

## Структура репозитория, важная для первичного знакомства

- server — Go-сервер управления
- firmware/esp8266 и firmware/esp32 — прошивка устройств
- deploy — файлы Docker Compose и Kubernetes
- docs — документация на английском и русском языках

## 1. Подготовьте окружение

Если нужно, создайте локальный файл окружения для сервера:

```bash
cp server/.env.example server/.env
```

Если пример файла отсутствует, создайте минимальный `.env` с настройками базы данных, порта REST, MQTT и при необходимости Kafka.

## 2. Запустите инфраструктурные зависимости

Для локальной разработки сначала поднимите вспомогательные сервисы:

```bash
docker compose -f deploy/docker-compose.yml up -d
```

Это запустит Kafka и Kafdrop локально.

## 3. Запустите сервер

Из каталога server:

```bash
cd server
go run ./server
```

Сервер инициализирует базу данных, подключится к MQTT при наличии конфигурации и запустит REST-интерфейсы.

## 4. Настройте устройство

Для нового ESP-устройства:

1. Прошейте прошивку под нужную платформу.
2. Включите устройство и дайте ему войти в режим настройки, если конфигурационный файл отсутствует.
3. Передайте параметры Wi-Fi и MQTT через процесс первоначальной настройки.
4. Перезагрузите устройство, чтобы оно подключилось к сети.

## 5. Зарегистрируйте и управляйте устройствами

После подключения устройства:

- проверьте, что оно появилось в реестре сервера
- изучите его статус и последние действия
- при необходимости отправьте новую конфигурацию
- отслеживайте сообщения состояния и логи через MQTT

## 6. Полезные команды

```bash
# получение списка устройств через REST API
curl -H "xToken: <TOKEN>" http://127.0.0.1/api/v1/devices

# загрузка CSV-реестра устройств
curl -H "xToken: <TOKEN>" -X POST http://127.0.0.1/api/v1/upload -F "body=@./tests/csv/devices.csv"
```

## Частые проблемы

- ошибка аутентификации: проверьте значение X-Token на сервере и в клиенте
- сообщения MQTT не приходят: проверьте адрес брокера, порт и корневой топик
- Kafka не обязателен для базовой работы: его можно отключить или закомментировать при старте
- конфликты портов возможны на локальной машине: проверьте активные слушатели перед запуском сервисов

## Следующие шаги

- сначала протестируйте сценарий с одним устройством
- добавьте небольшой CSV-список устройств
- проверьте обновления состояния через MQTT
- затем переходите к более крупному парку устройств или развертыванию через Docker/Kubernetes
