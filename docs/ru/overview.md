# Обзор продукта

## Назначение

Esp Monitor — это клиент-серверная платформа для настройки, обнаружения, мониторинга и удаленного управления устройствами на базе ESP. Она особенно полезна для установщиков, интеграторов и сервисных инженеров, которые разворачивают ESP-устройства в сетях клиентов и нуждаются в простом способе их настройки без физического доступа к каждой плате.

## Основные возможности

Платформа предоставляет следующие возможности:

- автоматическую или ручную регистрацию устройств
- первичную настройку Wi-Fi для новых плат
- удаленную передачу конфигурации по MQTT
- мониторинг состояния и телеметрии устройств
- базовые веб-интерфейсы администрирования и доступ через REST API
- при необходимости журналирование событий через Kafka
- поддержку прошивок для ESP8266 и ESP32

## Типовые сценарии использования

- развертывание партии ESP-устройств в здании или на объекте
- настройка Wi-Fi на первом включении
- удаленное обновление параметров после установки
- контроль доступности устройств в сети
- сбор событий для диагностики и аудита

## Архитектура продукта

Esp Monitor состоит из четырёх основных слоёв:

1. Прошивка устройства
   - работает на ESP8266 или ESP32
   - обеспечивает локальную настройку, подключение к Wi-Fi, обмен по MQTT и обработку действий устройства

2. Серверная часть
   - хранит метаданные устройств и состояние конфигурации
   - принимает обновления из веб-интерфейса или REST API
   - передает новые конфигурации устройствам через MQTT

3. Интерфейсы управления
   - веб-интерфейс для просмотра устройств и конфигурации
   - REST API для автоматизации и интеграций
   - примеры команд через curl

4. Инфраструктурные сервисы
   - MQTT-брокер для связи с устройствами
   - Kafka для журналирования событий
   - вспомогательные шаблоны развертывания на Docker и Kubernetes

## Карта компонентов

- каталоги firmware/esp8266 и firmware/esp32 содержат код устройства
- каталог server содержит Go-сервис управления
- каталог clients содержит примеры клиентов и вспомогательные инструменты
- каталог deploy содержит файлы Docker Compose и Kubernetes
- каталог docs содержит документацию проекта и инструкции по развертыванию

## Рабочий процесс

1. Устройство загружается и, если сохранённая конфигурация отсутствует, входит в режим настройки.
2. Устройство предоставляет локальный интерфейс для первичной настройки.
3. Пользователь задаёт параметры Wi-Fi и MQTT.
4. Устройство сохраняет конфигурацию локально и подключается к сети.
5. Сервер получает обновления состояния устройства и ведёт его реестр.
6. Сервер может передавать новые инструкции конфигурации и отслеживать активность устройства.

## Принципы проектирования

- упрощать первичную настройку устройств
- уменьшать объём ручных операций после установки
- использовать лёгкие механизмы обмена сообщениями
- поддерживать как локальную разработку, так и более близкое к production развертывание
- делать систему расширяемой для будущих интеграций

## Примечания для новых пользователей

Репозиторий представляет собой практический прототип, а не полностью выверенный коммерческий продукт. Некоторые части намеренно простые, а часть возможностей находится в процессе развития. Для большинства первых сценариев достаточно настроить одно устройство и подключить его к серверу, а затем расширять набор до небольшого парка устройств.
