# Руководство по серверу

## Роль сервера

Сервер является центральным управляющим компонентом Esp Monitor. Он хранит информацию о зарегистрированных устройствах, получает обновления их состояния, предоставляет точки управления и передает инструкции конфигурации устройствам через MQTT.

## Основные обязанности

- поддерживать список известных устройств и их метаданных
- хранить состояние конфигурации каждого устройства
- обслуживать веб-страницы и REST API
- получать обновления статуса от прошивки через MQTT
- отправлять новые команды конфигурации устройствам
- при необходимости публиковать логи и события в Kafka

## Базовая модель работы

Go-сервис при запуске инициализирует:

1. конфигурацию окружения
2. провайдер логирования и событий
3. подключение к базе данных
4. MQTT-слушатель
5. REST-сервер

## Хранение данных

По умолчанию сервер использует встроенную SQLite. В структуре проекта также есть слой для PostgreSQL, хотя он пока минимален.

## Точки входа API

Сервер предоставляет простой REST API для управления устройствами и загрузки списков. Типовые действия:

- вывод списка устройств
- фильтрация устройств по префиксу идентификатора
- загрузка CSV-списка устройств
- обновление конфигурации устройства
- удаление записи устройства

Эти точки предназначены как для веб-интерфейса, так и для автоматизации через скрипты.

## Веб-интерфейс

Встроенный веб-интерфейс позволяет оператору просматривать устройства и управлять ими без написания отдельного клиентского кода. Он намеренно лёгкий и ориентирован на практическую эксплуатацию.

## Примечания по эксплуатации

- аутентификация выполняется через значение X-Token
- сервер можно запускать локально для разработки или в Docker/Kubernetes для более крупных развертываний
- интеграция с Kafka необязательна, но полезна для наблюдаемости и обработки событий
- локальная разработка обычно проще, если MQTT и Kafka подняты через предоставленные ресурсы развертывания
