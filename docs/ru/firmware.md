# Руководство по прошивке

## Поддерживаемые платформы

Esp Monitor в настоящее время поддерживает прошивки для:

- ESP8266
- ESP32

Код прошивки находится в каталогах firmware/esp8266 и firmware/esp32.

## Обязанности прошивки

Встроенное ПО отвечает за:

- переход в режим настройки, если нет валидной сохранённой конфигурации
- приём начальных параметров Wi-Fi и MQTT
- сохранение конфигурации локально в JSON-файле
- подключение к Wi-Fi и синхронизацию времени
- объявление сервисов устройства и предоставление локального веб-интерфейса
- публикацию обновлений состояния через MQTT
- получение команд действий от сервера и их применение
- сброс конфигурации по запросу

## Процесс первичной настройки

Когда прошивка стартует без сохранённого файла конфигурации:

1. она запускает локальную точку доступа с настройками по умолчанию
2. открывает простой веб-сервис для приёма параметров настройки
3. принимает данные о Wi-Fi, MQTT и имени устройства
4. сохраняет конфигурацию и перезагружается

После перезагрузки устройство использует сохранённую конфигурацию для подключения к сети и регистрации на сервере.

## Поведение по MQTT

Прошивка использует MQTT для двух основных задач:

- публикации обновлений состояния устройства
- получения удалённых команд действий

Обновления состояния обычно содержат идентификатор устройства, служебную информацию и текущие значения пинов. Сервер может использовать эти данные для принятия решений о необходимости новой конфигурации или других действий.

## Удалённые команды

Прошивка может обрабатывать команды действий, передаваемые в соответствующие MQTT-топики. Если команда содержит объект конфигурации, устройство может обновить сохранённую конфигурацию, записать её и перезагрузиться. Набор действий постепенно расширяется в зависимости от потребностей проекта.

## Поведение при сбросе

Если пользователь инициирует длительное нажатие кнопки, устройство может очистить сохранённую конфигурацию и перезагрузиться. Это полезно, когда устройство нужно настроить заново.

## Практические советы

- используйте уникальные имена устройств и разные корневые топики MQTT для каждого развертывания
- храните учётные данные MQTT в секрете и не используйте публичные брокеры для production
- проверяйте журналы устройства при ошибках настройки
- используйте журналы сервера и MQTT-топики для проверки доставки сообщений
